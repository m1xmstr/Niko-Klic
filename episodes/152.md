# Episode 152 — Will the Picnic Message Run?

Status: Scheduled for November 11, 2026 at 3PM Central. Public playback verification waits for release.

[Watch Episode 152](https://youtube.com/shorts/DMI4Et-tjgg)

Nico and Klic need a message for a pretend picnic card. Before running the task, predict: will `rainy` match `sunny`?

Learning goal: compare a saved variable with a fixed word using Ansible's `when` condition. A false comparison skips this task; a true comparison lets it print its message.

## Predict on paper

Keep the rule `weather == "sunny"` and the message `PICNIC READY` unchanged.

| Saved `weather` value | Prediction | Observed in this lesson |
| --- | --- | --- |
| `rainy` | Print or skip? | Task skipped; no message |
| `sunny` | Print or skip? | Printed `PICNIC READY` |
| `rainy` in a fresh run | Print or skip? | Task skipped again |

These are fictional saved words, not a weather forecast. A printed message does not make the weather sunny or operate a device.

## Try with a grown-up

Use an existing Ansible installation on a local practice computer. This complete playbook targets only localhost, uses a local connection, gathers no facts, and only prints debug text. The video shows variable/task excerpts from it.

Save this as `picnic.yml` in a new practice folder:

```yaml
---
- name: Pretend picnic message
  hosts: localhost
  connection: local
  gather_facts: false
  vars:
    weather: rainy
  tasks:
    - name: Picnic message
      ansible.builtin.debug:
        msg: PICNIC READY
      when: weather == "sunny"
```

Check the syntax, then run it:

```sh
ansible-playbook -i localhost, --limit localhost picnic.yml --syntax-check
ansible-playbook -i localhost, --limit localhost picnic.yml
```

The comma after `localhost` makes it an inline inventory. Expect `skipping: [localhost]`; the recap has `failed=0`, `changed=0`, and `skipped=1`. Skipping because this condition is false is not a failed task.

Change **only** `weather: rainy` to `weather: sunny`. Leave the `when` condition and `msg` unchanged. Predict, then run the same command again. Expect `ok: [localhost]` with `"msg": "PICNIC READY"`; the recap has `failed=0` and `changed=0`.

Restore `weather: rainy` and rerun from a fresh terminal in that folder. The task should skip again. All three cases were executed in independent Ansible processes for this lesson; the temporary production fixture was removed afterward.

Try `weather: snowy` next. Explain your prediction before running. Does the saved word equal the fixed word `sunny`? Once finished, remove only the practice file and folder you created.

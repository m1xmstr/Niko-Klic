Nico only needs to read a pretend route card. Does he need reading access, or reading **and** writing access? Match access to the task, then check what actually happens.

## Try it with a grown-up

Use an ordinary, non-root Linux account with GNU Coreutils in a new disposable folder. Do not use `sudo`, valuable files, or an existing destination. These commands create a fictional route and give its owner read permission without write or execute permission:

```sh
practice_dir=$(mktemp -d)
cd "$practice_dir"
printf '%s\n' 'bridge then pond' > route.txt
chmod 400 route.txt
stat -c '%a' route.txt
cat route.txt
sha256sum route.txt
```

Our recorded mode was `400`; reading printed `bridge then pond`. Predict what this ordinary append attempt will do:

```sh
printf '%s\n' 'extra stop' >> route.txt
```

Our shell returned **Permission denied**, with a nonzero exit status. Reading still worked and the checksum remained unchanged. Read permission was enough for this task; write permission was unnecessary.

## Change the case

Make a second practice file and predict the same two operations:

```sh
printf '%s\n' 'pond then tower' > next.txt
chmod 400 next.txt
cat next.txt
printf '%s\n' 'extra stop' >> next.txt
cat next.txt
sha256sum next.txt
```

Our read succeeded, append was denied, and the contents stayed `pond then tower`. A fresh shell confirmed both modes and contents, denied another append, and checked the second checksum. A separate disposable `600` control file allowed its ordinary owner to append text, showing why the extra permission matters.

## What this proves

`400` grants the owner read permission and grants no permissions to the group or others. `600` grants the owner both read and write. The lesson covers normal file reads and writes by an ordinary user. **It is not an immutable lock:** the owner can change the file's permissions again; privileged users can have additional access. Deletion depends on the containing directory's permissions. See the [GNU permission guide](https://www.gnu.org/software/coreutils/manual/html_node/Setting-Permissions.html) and [chmod reference](https://www.gnu.org/software/coreutils/manual/html_node/chmod-invocation.html).

The animated cards illustrate actual recorded checks on disposable fictional files. No route service, account sharing, or real equipment was changed. Our practice files were removed after verification.

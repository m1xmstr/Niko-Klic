# Episode 149 — Same Frame, New Color!

Status: Scheduled for November 10, 2026 at 10AM Central. Public playback verification waits for release.

[Watch Episode 149](https://youtube.com/shorts/nB0PYSmWxZI)

Nico wants two labels for a pretend parade. An Ansible message can keep its fixed words and punctuation while inserting a variable's value.

## Predict the whole message

Start with `color: blue`. The message template is `"Flag: {{ color }}!"`. What will be printed? Keep track of three parts: the fixed prefix `Flag: `, the inserted color, and the fixed `!`.

Our real localhost Ansible run printed `Flag: blue!`. Changing only the variable to `red` produced `Flag: red!`. A third independent process repeated the blue case and printed `Flag: blue!` again. Each run completed with `changed=0` and `failed=0`: these are debug messages, not physical flags or file-writing tasks.

## Try it with a grown-up

Use an existing Ansible installation and save this as `parade.yml` in a new disposable practice directory:

```yaml
---
- name: Pretend parade label
  hosts: localhost
  connection: local
  gather_facts: false
  vars:
    color: blue
  tasks:
    - name: Print the label
      ansible.builtin.debug:
        msg: "Flag: {{ color }}!"
```

Check its syntax, then run only this local playbook:

```sh
ansible-playbook -i localhost, --limit localhost parade.yml --syntax-check
ansible-playbook -i localhost, --limit localhost parade.yml
```

The recorded message excerpt is:

```text
"msg": "Flag: blue!"
```

Change only `color: blue` to `color: red`. Predict the complete message before running the same command again:

```text
"msg": "Flag: red!"
```

The debug task and message template remain identical. The colon, space, capital F, and exclamation mark come from fixed text. The braces evaluate the variable; the output does not print those braces. Ansible's [templating documentation](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_templating.html) explains Jinja expressions, and the [debug module reference](https://docs.ansible.com/projects/ansible/latest/collections/ansible/builtin/debug_module.html) describes `msg`.

The screen shows separate variable and task excerpts for readability; the complete runnable playbook above includes their proper YAML nesting. Do not paste those abbreviated screen excerpts as a full playbook.

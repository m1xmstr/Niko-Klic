# Episode 147 — A File, Not a Folder!

Status: Scheduled for November 9, 2026 at 10AM Central. Public playback verification waits for release.

[Watch Episode 147](https://youtube.com/shorts/mOHqR7uDvZ8)

Nico’s pretend star show needs a regular file. Two paths have the same final name, but one is a directory. Combine an exact name with `-type f` to select only regular files.

## Try it with a grown-up

Use an ordinary user in Linux with GNU find. Start in a new disposable practice directory. This example creates invented data and does not touch system files.

```sh
practice=$(mktemp -d)
cd "$practice"
mkdir -p art/one art/two/star.txt
printf 'STAR\n' > art/one/star.txt
find art -name 'star.txt'
```

The name-only search reports both paths, because both final names match. Output order is not guaranteed and does not affect this lesson:

```text
art/one/star.txt
art/two/star.txt
```

Now require a regular file as well:

```sh
find art -type f -name 'star.txt'
```

Our real Linux run returned only:

```text
art/one/star.txt
```

The name test and type test must both be true. The quotes protect the pattern from shell expansion. `find` reports a matching path here; it does not open or move the file.

## Change the kinds

Inside that same disposable directory, swap which path is a file and which is a folder. The two path names stay the same. These commands intentionally remove only the invented file and empty folder we just created:

```sh
rm art/one/star.txt
rmdir art/two/star.txt
mkdir art/one/star.txt
printf 'STAR\n' > art/two/star.txt
find art -type f -name 'star.txt'
```

Predict first. Our changed run returned `art/two/star.txt`. A new shell independently repeated the search and got that same result. A name-only control still returned both paths. The type filter follows the actual kind, not the `.txt` ending.

## What this proves

`-type f` selects regular files, while `-type d` selects directories. This demonstration uses real regular files and directories with GNU find’s default symbolic-link behavior; it does not cover following symbolic links, permissions errors, or every filesystem type. The star show is a fictional illustration. No physical show equipment is controlled. See the [GNU find type-test documentation](https://www.gnu.org/software/findutils/manual/html_node/find_html/Type.html).


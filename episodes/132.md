## What we are learning

A machine-learning model trained on a narrow collection can fail on different examples. Compare a tiny fixed training set with varied training, and keep test answers separate. Prerequisites: [122](122.md) and [127](127.md).

Nico tilts a large triangle exhibit while Klic moves a fresh test tray through a shape museum. The separate command and output panels show a recorded software test. The characters illustrate the lesson; software does not control a physical robot.

## Actual demonstration

This standard-library Python example finds the nearest class center using squared Euclidean distance. Each row has two **hand-entered numeric features**: number of corners and size in fictional units. It does not recognize pictures. The rule and all datasets were fixed before running either test; the algorithm and feature units stay the same in both runs.

|Set|Triangles: [corners, size]|Squares: [corners, size]|
|---|---|---|
|Narrow training|[3,2], [3,3]|[4,8], [4,9]|
|Extra training for varied run|[3,7], [3,10]|[4,1], [4,4]|
|First held-out test|[3,8]|[4,3]|
|Fresh held-out test|[3,6]|[4,6]|

The varied run uses the original training rows plus the extra training rows. No test row is in either training set, and the two test sets are disjoint. Predictions are saved before the program loads the answer file. The complete fixture files and runnable program are in [examples/132](../examples/132/).

With a grown-up and Python 3, download that directory together, open a terminal there, and run each command on **one line**:

```sh
python3 shape_test.py --set narrow
```

Recorded output:

```text
test: narrow
correct: 0 / 2
```

The big triangle was predicted as square, and the small square as triangle. With unscaled features, size dominates this deliberately narrow training example.

Changed run:

```sh
python3 shape_test.py --set varied
```

Recorded output:

```text
test: varied
correct: 2 / 2
```

The second run uses two **fresh** test rows. Both are predicted correctly, but two successes are not proof of general accuracy. This is a constructed teaching example; adding data does not guarantee improvement, and changing feature units can change this model's decisions. The production demonstration ran locally in a disposable folder that was removed afterward.

## Runnable model code

```python
import argparse,json
from pathlib import Path
p=argparse.ArgumentParser();p.add_argument('--set',choices=['narrow','varied'],required=True);args=p.parse_args()
training=json.loads(Path(args.set+'-train.json').read_text())
test=json.loads(Path(args.set+'-test.json').read_text())
centers={}
for label in sorted({row['label'] for row in training}):
    rows=[row['features'] for row in training if row['label']==label]
    centers[label]=[sum(col)/len(rows) for col in zip(*rows)]
predictions=[]
for row in test:
    distances={label:sum((x-y)**2 for x,y in zip(row['features'],center)) for label,center in centers.items()}
    predictions.append({'id':row['id'],'prediction':min(distances,key=distances.get),'distances':distances})
# Persist every prediction BEFORE loading any held-out answer.
Path(args.set+'-predictions.json').write_text(json.dumps(predictions,indent=2))
answers=json.loads(Path(args.set+'-answers.json').read_text())
correct=sum(row['prediction']==answers[row['id']] for row in predictions)
Path(args.set+'-model.json').write_text(json.dumps(centers,indent=2))
print('test: '+args.set)
print('correct: '+str(correct)+' / '+str(len(test)))
```

Algorithm background: [scikit-learn NearestCentroid documentation](https://scikit-learn.org/stable/modules/generated/sklearn.neighbors.NearestCentroid.html). This example implements the basic nearest-center rule directly and does not require that package.

## Predict and explain

- **What was missing from narrow training?** Larger triangles and smaller squares.
- **Should test answers be training examples?** No. Keep them separate so the test can expose mistakes.
- **Does 2 of 2 prove the model always works?** No. It only describes these two examples.

## Grown-up activity

Make paper triangles and squares in varied pretend sizes. Build one collection with only small triangles and big squares, then compare it with a more varied collection. Keep some new cards aside. Discuss what the first collection leaves out and why fresh examples are useful for testing. This paper activity is an analogy, not a measured model result. Use no personal data or online account.

Recap: **Vary the examples. Test on something new.**

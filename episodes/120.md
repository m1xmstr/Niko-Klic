# Episode 120 — Which Task Comes First? Meet Ansible

**Learning objective:** Explain that Ansible automates computer tasks described in a playbook, and that dependent tasks need a suitable order.

**Prerequisites:** Understanding that a procedure has steps. Episode 4 introduces sequences; no Python or YAML knowledge is needed here.

Nico and Klic work at a sunny garden bench. Nico unfolds a pretend folder while Klic places a note inside and stamps a completion card. Their two task cards represent a tiny computer workflow: make a folder, then save a note in it. They replace WELCOME with HELLO and check that the new note is in the same folder.

This is a **physical model**, not a running Ansible demonstration. The two task cards are ordinary language, not valid YAML. No software is installed or computer changed.

| Term | Meaning in this lesson |
|---|---|
| Automation | Having software perform specified tasks |
| Ansible | A tool for automating computer tasks |
| Playbook | An Ansible automation document containing plays and tasks |
| Task order | A dependent task needs its prerequisite ready first |

Ansible playbooks are written in YAML. By default, tasks execute in their specified order. This introductory model does not cover conditions, loops, failures or different execution strategies. Automation follows instructions; this example is not a model learning from demonstrations. See the [official Ansible playbook introduction](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_intro.html).

## Predict, reveal, change

- **Predict:** Which comes first: make the folder or save the note inside it?
- **Reveal:** Make the folder first. Saving a file inside a directory requires that directory to exist.
- **Change:** Replace WELCOME with HELLO. The task order stays the same; the note content changes.
- **Check:** There is one folder, containing the intended new note.
- **Recall:** Does Ansible learn this task list by watching the characters? No. The playbook supplies the tasks.

## Grown-up activity

1. Draw two cards: “Make a folder” and “Save a note inside.”
2. Help your learner put them in order.
3. Use a paper folder and a fictional WELCOME note to act out the model.
4. Replace the note with HELLO and repeat the check.
5. Ask why order matters here. Answer: the destination must exist before the note can go inside it.

No account, installation, personal information or commands are needed. A later lesson introduces actual YAML and a disposable localhost Ansible example. This guide makes no claim that the current physical model executed a playbook.

# Episode 129 — A Home for Empty Files! Linux mkdir and touch

**Objective:** Create a new practice folder and empty files, then check their names.

**Prerequisites:** [Episode 124](124.md): terminal, folders, `pwd`, `ls` and `cd`.

**Status:** [Watch the published lesson](https://www.youtube.com/watch?v=N4d2dYpX1n0). Public playback and manual English captions verified October 28, 2026.

## Story

Nico types at a keyboard while Klic helps compare the example and its result. Large terminal panels keep the input and recorded output visible. The animation illustrates recorded software demonstrations; it does not control live hardware.

## Try it with a grown-up

Use an empty, disposable practice directory in Linux. A grown-up should open it in the terminal and verify its location before running these commands. Do not use personal files. These are local commands; no accounts, remote hosts or administrator privileges are needed.

A grown-up can create a unique practice directory and enter it:

```sh
practice_dir=$(mktemp -d)
cd "$practice_dir"
export LC_ALL=C
```

In this empty directory, run the exact first example:

```sh
mkdir art
touch art/star.txt
ls art
```

Output:

```text
star.txt
```

- `mkdir art` creates a directory named `art`. This example requires that it does not already exist.
- `touch art/star.txt` creates an empty file because that file does not exist yet.
- `/` separates the directory name from the filename.
- `ls art` lists the names inside `art`. It does not display file contents.
- `mkdir` and `touch` normally print nothing when these commands succeed. The displayed name comes from `ls`.

**Predict:** What name will the first listing show?

**Answer:** `star.txt`. Its contents are empty.

## Change one thing

Keep the same practice folder. Create a second new filename:

```sh
touch art/moon.txt
ls art
```

Recorded output with `LC_ALL=C`:

```text
moon.txt
star.txt
```

Both files remain in the same `art` directory. In the production proof, a fresh shell reopened that directory and independently confirmed that both files existed and each contained **zero bytes**. The fixture was then removed and the dedicated Linux VM stopped. The exact examples ran on Linux 6.12.13, Fedora CoreOS 41, with GNU coreutils 9.5. The runtime identifies the proof environment; it is not an installation recommendation.

## Important distinction

For a **new filename**, `touch` creates an empty file. If a file already exists, `touch` normally updates timestamps and preserves its existing contents. It is not an eraser, a text editor or a drawing command. The `.txt` suffix is a naming convention; it does not insert text.

This lesson teaches creation and listing. Writing and reading file contents will be separate lessons.

## Check understanding

1. **Does `mkdir art` make a picture?** No. It makes a directory called `art`.
2. **Does `touch art/star.txt` draw a star?** No. For this new filename it creates an empty file.
3. **Why do both names appear after the changed example?** We added a second file without removing the first.
4. **Does seeing a name prove the file contains text?** No. Listing names and reading contents are different operations.

## Grown-up activity

Choose two fictional filenames in a fresh practice folder. Predict the listing, create the files and compare the result. Keep the file cards blank until a later lesson actually writes content. A grown-up can remove this disposable folder afterward using the file manager after confirming its location; do not practice deletion on personal files.

**Recap:** Make the folder, create the files, then check.

# Episode 135 — One Name, Two Greetings! Ansible Variables

Status: Corrected terminal-and-typing edition scheduled for October 30, 2026 at 10AM Central. Public playback and manual English verification are pending release.

## What we are learning

An Ansible variable holds a named value. Keep a task unchanged and change the value it uses. Prerequisites: [Episode 125 — YAML](125.md) and [Episode 130 — repeatable tasks](130-ansible-idempotence.md).

Nico types the Ansible variable example while Klic compares the recorded greetings. Large code and output panels show the changed name and unchanged task.

## Try the exact playbook with a grown-up

Use an existing Ansible installation and a new empty practice folder. Save this complete plain-text file as `greeting.yml`, preserving spaces:

```yaml
- hosts: localhost
  connection: local
  gather_facts: false
  vars:
    guest: Nico
  tasks:
    - ansible.builtin.debug:
        msg: "Hello, {{ guest }}!"
```

The variable is named `guest`; its initial value is `Nico`. `{{ guest }}` inserts that value into the message. The quoted message is part of a YAML playbook, not a Python program.

Check the syntax and then run only against this computer:

```sh
ansible-playbook -i localhost, --limit localhost --syntax-check greeting.yml
ansible-playbook -i localhost, --limit localhost greeting.yml
```

The comma in `localhost,` makes an inline inventory. `connection: local` and `--limit localhost` keep this example local. The debug task reports a message; it does not modify a remote machine.

Recorded message field:

```text
Hello, Nico!
```

The full run also prints play/task headings and a recap: `ok=1 changed=0 unreachable=0 failed=0`.

## Change one value

Change only `guest: Nico` to `guest: Klic`, save the file, and run the same command again. The full changed file is:

```yaml
- hosts: localhost
  connection: local
  gather_facts: false
  vars:
    guest: Klic
  tasks:
    - ansible.builtin.debug:
        msg: "Hello, {{ guest }}!"
```

Predict the greeting before running it:

```sh
ansible-playbook -i localhost, --limit localhost greeting.yml
```

Recorded message field:

```text
Hello, Klic!
```

The task is byte-for-byte identical. The named value changed. Both syntax checks and runs succeeded with no failed tasks and no changed resources. Demonstration environment: macOS, ansible-core 2.18.5. The disposable practice folder was removed afterward. These details describe the recorded example; no Linux execution is claimed here.

See the [official Ansible variables guide](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_variables.html).

## Predict and explain

- Which part is the variable name? `guest`.
- Which part changes in the second run? Its value, from `Nico` to `Klic`.
- What stays unchanged? The debug task and its `{{ guest }}` reference.
- Is this a printed ticket? No. The result is terminal text; the paper card is an analogy.

## Grown-up activity

Write “Hello, [guest]!” on a card and exchange a separate pretend-name tile. Predict the greeting each time. Then choose another fictional name, change only the variable value in the playbook, save it and run the same local command. Compare the result with your prediction.

# Episode 85: Does Double Really Double? Python assert Tests

Video in preparation; no native schedule yet.

**Learning goal:** Check one known function result with assert, then compare a new call and a broken implementation.

**Prerequisites:** [Lesson 52](./52.md), [Lesson 64](./64.md), [Lesson 75](./75.md), [Lesson 80](./80.md), [Lesson 83](./83.md), [Lesson 84](./84.md).

## Working example

With a grown-up, use a local Python 3 editor and a new empty practice folder. No account or private information is needed.

```python
def double(n):
    return n * 2
assert double(3) == 6
print(double(4))
```

Expected terminal output:

```text
8
```

assert double(3) == 6 checks a known case. True lets this normal Python run continue; False raises AssertionError. One passing test does not prove every possible input.

## Change one input

```python
def double(n):
    return n * 2
assert double(3) == 6
print(double(5))
```

Expected terminal output:

```text
10
```

## What the story shows

Run normal Python without optimization flags for this learning test. assert is a development check, not an access-control or security mechanism. Python does not operate the paper plane or measuring jig.

## Try it together

With a grown-up, run the complete example normally in a local Python editor. Predict eight. Change only the final call to double(5), then predict ten and rerun. Restore it and temporarily change the function to return n * 3: the known check raises AssertionError before print. Restore n * 2. A passing case does not prove all inputs.

## Read the error

```python
def double(n):
    return n * 3
assert double(3) == 6
print(double(4))
```

This run raises `AssertionError`. Read the final error line, inspect the instruction that caused it, correct the program, and rerun.

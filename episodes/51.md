# Episode 51: Can One Function Cheer for Both Friends?

[Watch Episode 51](https://youtube.com/shorts/u8gUhgPzF_c)

**Learning goal:** A parameter is a named input to a function. A call supplies the value for that run.

**Prerequisites:** [Episode 27](./27.md), [Episode 44](./44.md).

## Try the real Python

Run this in a local Python 3 environment with a trusted grown-up. The terminal displays the output; the code does not move story props.

```python
def cheer(name):
    print("Great job,", name)

cheer("Nico")
cheer("Klic")
```

Expected terminal output:

```text
Great job, Nico
Great job, Klic
```

## Change one thing

Predict the result before running this fresh example.

```python
def cheer(name):
    print("Great job,", name)

cheer("Robot")
```

Expected terminal output:

```text
Great job, Robot
```

## Try it together

Use fictional name cards and predict each greeting without changing the function body. Write the predicted output on paper first, run with a grown-up, and compare. Use fictional names and practice values.

## Read the important line

`def cheer(name):` defines the function; the indented line is its body. Defining it does not run the body. `cheer("Nico")` calls it: the argument `"Nico"` becomes the value of the parameter `name` for that call. A new argument makes a new greeting without rewriting the body.

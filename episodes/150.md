# Episode 150: Which Lines Finish the Log?

Status: Scheduled for November 10, 2026 at 3PM Central. Public playback verification waits for release.

[Watch Episode 150](https://youtube.com/shorts/FeyrZfkIk4E)

Nico and Klic find the ending of a saved pretend show log with Linux `tail`. They change the number of lines to read, while the file stays intact.

## Try it with a grown-up

Use a new practice folder and a disposable file called `show.log` containing:

```text
09:00 doors opened
09:01 lights on
09:02 music started
09:03 show began
```

Predict before running:

```sh
tail -n 2 show.log
```

Does it print the first two lines or the last two?

```text
09:02 music started
09:03 show began
```

Now change only the count:

```sh
tail -n 3 show.log
```

Which extra line appears?

```text
09:01 lights on
09:02 music started
09:03 show began
```

`tail -n N` prints the last N lines of this saved file. It preserves their file order and does not remove earlier lines. It does not sort timestamps: the last saved line need not have the latest timestamp. This example reads a saved file once; it does not monitor live events.

## One more prediction

Try `tail -n 1 show.log`. Predict the complete line before running it. Then read the original file to check that all four lines remain.

## What was demonstrated

The base, changed-count, and fresh-shell cases ran with GNU `tail` as an ordinary user in Linux. The source file's contents and hash stayed unchanged. Separate controls compared the first two lines and confirmed that deliberately unordered timestamps remained in file order. The show and its events are fictional; the command results are real.

Reference: [GNU Coreutils: tail](https://www.gnu.org/software/coreutils/manual/html_node/tail-invocation.html).

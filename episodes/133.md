## What we are learning

A token is a piece used to represent text for a language model. A token is not necessarily a whole word or a syllable. We inspect two inputs with one named tokenizer and count its actual pieces. Prerequisite: [Episode 123](123.md).

Nico types at a keyboard while Klic compares the recorded tokenizer results. Separate input and output panels show how the named tokenizer splits the words.

## Actual demonstration

This example uses **tiktoken 0.14.0** and the **cl100k_base** encoding. It tokenizes text locally; it does not ask a language model for an answer. Different encodings, spaces, capitalization, and punctuation can change token boundaries.

With a grown-up, save [pieces.py](../examples/133/pieces.py) in a practice folder. Create and activate a Python virtual environment, then install the pinned dependency:

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install tiktoken==0.14.0
```

These setup commands use a macOS/Linux shell. The first encoding load may download its public encoding data. The word itself is processed locally, and no model API is called. Use only the pretend words here.

Run:

```sh
python3 pieces.py rainbow
```

Recorded output:

```text
pieces: rain | bow
tokens: 2
```

Changed input:

```sh
python3 pieces.py rainbows
```

Recorded output:

```text
pieces: rain | bows
tokens: 2
```

One piece changes, while the count stays two. The vertical bar is our display separator; it is not part of either word. Both token sequences decode back to the exact input. These results apply to these inputs and this encoding, not every tokenizer.

## Runnable code

```python
import sys
import tiktoken

text = sys.argv[1]
enc = tiktoken.get_encoding('cl100k_base')
ids = enc.encode(text)
assert enc.decode(ids) == text
pieces = [enc.decode_single_token_bytes(i).decode('utf-8') for i in ids]
print('pieces: ' + ' | '.join(pieces))
print('tokens: ' + str(len(ids)))
```

This small display helper is intended for the simple ASCII examples above. A token can contain only part of a multibyte Unicode character, so decoding each token separately as UTF-8 is not a general text-display method. The complete token sequence can still be decoded with `enc.decode(ids)`.

Background: [OpenAI's tiktoken repository](https://github.com/openai/tiktoken) explains byte-pair encoding and reversible subword tokenization.

## Predict and explain

- **Does one word always mean one token?** No. Here, `rainbow` becomes two tokens.
- **Does adding a letter always increase the count?** No. Here the last piece changes from `bow` to `bows`, and the count stays two.
- **Do the pieces prove the model understands the word?** No. This demonstration only splits and reconstructs text.

## Grown-up activity

Write `rain` and `bow` on two paper pieces, then replace `bow` with `bows`. Count the pieces. Explain that paper pieces are an analogy; the actual tokenizer chooses its boundaries. With a grown-up, predict and run another simple pretend ASCII word, then compare the real pieces. Do not enter names, secrets, or personal information.

Recap: **Count tokens, not just words. Check the actual pieces.**

# Episode 125 — Where Does the Message Belong? Ansible YAML

**Status:** Published October 22, 2026; public playback and manual English captions verified.

[Watch Episode 125](https://youtube.com/shorts/CFQuBd4zChM).

**Subject:** Ansible and YAML. **Prerequisite:** Episode 120, an introduction to ordered automation tasks.

**Learning goal:** Read a small playbook, keep its indentation, and change one greeting. This example only displays terminal text.

Nico slides a greeting card into a recipe rack while Klic checks its grouping. The cards are a physical model. The terminal excerpt comes from an actual Ansible run; the cards are not computer output and Ansible does not move them.

## A complete practice playbook

With a grown-up, use a temporary practice folder on a computer with Ansible installed. Save this as `greeting.yml`. Use spaces, not tabs, and preserve the indentation shown.

```yaml
- hosts: localhost
  connection: local
  gather_facts: false
  tasks:
    - ansible.builtin.debug:
        msg: "Hello, Nico!"
```

- `hosts: localhost` selects the same computer running Ansible in this example.
- `connection: local` selects a local connection.
- `gather_facts: false` skips collecting system facts.
- `tasks` contains a list. The dash introduces its single task.
- `ansible.builtin.debug` displays a message. `msg` belongs to that task and is indented farther.
- The colon separates a key from its value; quotes surround our greeting text.

## Run and check

Use an explicit practice inventory and limit:

```sh
ansible-playbook -i localhost, --limit localhost greeting.yml --syntax-check
ansible-playbook -i localhost, --limit localhost greeting.yml
```

The comma after `localhost` is intentional: this is an inline inventory containing one host. Do not substitute a work or production inventory.

Recorded message excerpt:

```text
ok: [localhost] => {
    "msg": "Hello, Nico!"
}
```

The actual run completed with `ok=1`, `changed=0`, `unreachable=0`, and `failed=0`. This debug task did not modify the computer. The example was checked using Ansible core 2.18.5 on macOS localhost in a temporary practice folder. It is not a Linux execution claim. The temporary files were removed after verification.

## Predict, then change one value

What happens if we keep the spaces and change only `Nico` to `Klic` inside the greeting?

Save the changed line as:

```yaml
        msg: "Hello, Klic!"
```

Run the same commands again. The recorded message becomes:

```text
ok: [localhost] => {
    "msg": "Hello, Klic!"
}
```

The changed run also had `changed=0` and `failed=0`. A different displayed message does not mean Ansible modified the machine.

## Questions and answers

**Why keep the spaces?** YAML uses indentation to express grouping. Here the message option belongs beneath the debug task.

**Did Ansible print a paper card?** No. It displayed terminal text; Nico and Klic moved model cards by hand.

**Does this playbook contact another computer?** No. This example explicitly targets localhost and uses only a debug message.

## Grown-up activity

Write `tasks`, `debug`, and a fictional greeting on three cards. Place each child card a little farther to the right to model grouping. Then copy the complete playbook into a separate practice folder, change only the greeting, and compare the terminal result. Keep real names, passwords and work inventories out of the activity. An adult should manage installation and execution; children can predict and check the message.

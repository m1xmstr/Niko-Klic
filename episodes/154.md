# Episode 154 — One Map or Two?

Scheduled for November 12, 2026 at 3 PM America/Chicago. Public playback and manual-caption verification wait for release.

[Watch Episode 154](https://youtube.com/shorts/7JbuS7BsQd8)

Nico's pretend treasure team needs a spare map. Before running `cp map.txt copy.txt`, predict: will the original remain? This lesson copies a regular text file into a new destination, then checks both names and contents.

| Case in its own fresh folder | Command | Observed after the command |
| --- | --- | --- |
| Base | `cp map.txt copy.txt` | Both names exist; both contain `START HERE` |
| Change only the new name | `cp map.txt spare.txt` | Both names exist; both contain `START HERE` |
| Fresh-shell repeat | `cp map.txt copy.txt` | The same two files and matching contents |

All three cases were actually run as an ordinary user in a local Linux practice VM. The source hashes stayed unchanged, the copies matched, and each source and destination had different inode numbers. A separate check edited the copied file and verified that the original still contained `START HERE`. Production practice folders were removed and the VM stopped afterward.

## Try with a grown-up

Use an existing Linux practice environment. These commands create only disposable text files in a new temporary folder. Do not substitute personal files. `cp` can replace an existing destination, so check the new name first. This small example is not a complete backup system.

```sh
practice_dir=$(mktemp -d)
cd "$practice_dir" || exit 1
printf 'START HERE\n' > map.txt
ls -1
cat map.txt

# Predict before running. Continue only when copy.txt is absent.
test ! -e copy.txt && cp map.txt copy.txt
ls -1
cat map.txt
cat copy.txt
cmp map.txt copy.txt
```

Expect both `copy.txt` and `map.txt` from `ls`, and `START HERE` from each `cat`. `cp` normally prints nothing on success. The video's result panel summarizes the checks after copying; it is not output printed by `cp`. `cmp` prints nothing and returns success when these files have identical contents. If a command reports an error, investigate it rather than assuming the copy worked.

Repeat in another fresh practice folder, changing only `copy.txt` to `spare.txt`. Keep `map.txt` and its text unchanged. Predict which two names should remain. Repeat the original case from a fresh shell as well.

To test independence in one of your own practice folders:

```sh
printf 'COPY ONLY\n' > copy.txt
cat copy.txt
cat map.txt
```

The copy now says `COPY ONLY`; the original still says `START HERE`. Once finished, remove only the practice files and temporary folders you created.

# Episode 102: Choose What to Share! Python Field Allowlist

Natively scheduled for **2026-10-16T10:00:00-05:00 (America/Chicago)**. Public playback and manual English captions will be checked after release.

**Learning goal:** Copy only selected dictionary fields into a new dictionary using a loop and an allowlist.

**Prerequisites:** [Lesson 54](./54.md), [Lesson 66](./66.md), [Lesson 67](./67.md), [Lesson 72](./72.md).

## Working example

With a grown-up, use a local Python 3 editor and a new empty practice folder. No account or private information is needed.

```python
profile = {"nickname": "Star", "room": "Blue"}
allowed = ["nickname"]
public = {}
for key in allowed:
    public[key] = profile[key]
print(public)
```

Expected terminal output:

```text
{'nickname': 'Star'}
```

The loop copies only keys named in allowed. All allowed keys must exist in profile for this simple version. This data selection does not encrypt or protect the original dictionary and does not publish anything.

## Change one input

```python
profile = {"nickname": "Moon", "room": "Blue"}
allowed = ["nickname"]
public = {}
for key in allowed:
    public[key] = profile[key]
print(public)
```

Expected terminal output:

```text
{'nickname': 'Moon'}
```

## What the story shows

Only fictional practice fields are used. The program prints a new dictionary locally. It does not share it online, enforce access control, or protect the original data.

## Try it together

With a grown-up, run the example and check that room is absent from the printed dictionary. Change only Star to Moon; predict the new nickname. Keep all data fictional. Explain why the original profile still contains room and why this is not an access-control system.

# Episode 155 — Read It or Run It?

Scheduled for November 13, 2026 at 10 AM America/Chicago. Public playback verification awaits release.

[Watch episode 155](https://youtube.com/shorts/YF5FuYHgGsQ)

Our pretend puppet show needs an opening cue. A known practice script prints `SHOW READY`. We read it, try to start it directly, change only its owner's execute permission, and try again.

| Check | Owner permissions | Reading with `cat` | Direct start `./cue.sh` |
| --- | --- | --- | --- |
| Base | Read only (400) | Script text | Permission denied |
| Add only owner execute | Read and execute (500) | Same script text | SHOW READY |
| Remove execute; fresh shell | Read only (400) | Same script text | Permission denied |

These cases actually ran as an ordinary, non-root user in a local Linux VM. Script hashes remained identical. A separate control, `sh cue.sh`, printed `SHOW READY` while the file was still mode 400. The shell reads and interprets the file; it does not need that file's execute bit for this invocation. The production fixture was removed and the VM stopped afterward.

## Try with a grown-up

Use an existing Linux practice environment and only this known, harmless script. It prints a message; it does not open a real stage, operate a device, or access personal files. Reading permission, execute permission, and understanding whether code is safe are different things.

```sh
practice_dir=$(mktemp -d)
cd "$practice_dir" || exit 1
cat > cue.sh <<'SCRIPT'
#!/bin/sh
printf 'SHOW READY\n'
SCRIPT
chmod 400 cue.sh
cat cue.sh
stat -c %a cue.sh
sha256sum cue.sh

# Predict, then try the direct start. Permission denied is expected.
./cue.sh

# Change only owner execute permission; inspect the script again.
chmod u+x cue.sh
cat cue.sh
stat -c %a cue.sh
sha256sum cue.sh
./cue.sh
```

Compare the two hashes. The mode changes from 400 to 500; the contents do not change. The second direct start prints `SHOW READY`. Repeat after `chmod u-x cue.sh` from a fresh shell: reading still works, while the direct start is denied again.

For this exact inspected practice script, test the distinction:

```sh
chmod 400 cue.sh
sh cue.sh
```

This prints the message even without the script's execute bit. Removing that bit is not a sandbox or a guarantee that readable code cannot run. Never use permission changes as a substitute for understanding unfamiliar code. These results concern ordinary files, the owner, and this environment; directory traversal permissions, mount options, other users, and additional security policies can also affect execution.

When done, remove only `cue.sh` and the temporary folder you created. No broad permission changes or administrator privileges are needed.

## Explain it back

- Why could we read the script before the direct start worked?
- Which single permission changed, and what stayed identical?
- Why did `sh cue.sh` work at mode 400?
- Why does execute permission not establish that a script is safe?

# Episode 146 — Need a Map First!

Status: Scheduled for November 6, 2026 at 3PM Central. Public playback verification waits for release.

[Watch Episode 146](https://youtube.com/shorts/CZwuHqIs8Ec)

Nico's pretend walk needs a map. Ansible can check that requirement before continuing to the next task. Predict what happens with `rope`, then change just that value to `map`.

## Try it with a grown-up

Save this complete playbook as `kit.yml` in a new disposable practice folder. It targets only `localhost`, gathers no facts, and runs only an assertion and a printed message. Use an installed Ansible environment; do not add remote hosts, privilege escalation, `ignore_errors`, or a rescue block.

```yaml
---
- name: Pretend route check
  hosts: localhost
  connection: local
  gather_facts: false
  vars:
    kit: rope
  tasks:
    - name: Check the kit
      ansible.builtin.assert:
        that:
          - kit == 'map'
        fail_msg: NEED MAP
        success_msg: CHECK PASSED
    - name: Route message
      ansible.builtin.debug:
        msg: WALK READY
```

Check its syntax, then run it with an explicit local inventory:

```sh
ansible-playbook -i 'localhost,' --limit localhost kit.yml --syntax-check
ansible-playbook -i 'localhost,' --limit localhost kit.yml
```

With `kit: rope`, our real run printed **NEED MAP**, returned a nonzero exit status, and reported `failed=1`. The following `Route message` task did not run, so **WALK READY** was not printed. The check caught a value that did not meet the rule.

## Change one value

Change only `kit: rope` to `kit: map` and run the same command. Our assertion printed **CHECK PASSED**, and the next task printed **WALK READY**. The recap showed `failed=0` and `changed=0`. An independent fresh run with `rope` failed again and did not run the next task.

## What this proves

`ansible.builtin.assert` checks expressions under `that`. Here the string value must equal `map`. With default error handling, the failed task stops subsequent tasks for this host in this play. This is different from a false `when` condition, which skips a task. Error-handling options can change that behavior; this example uses none. The check tests this specific value, not whether an entire real-world plan is safe. See the [default error-handling documentation](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_error_handling.html) and [official assert documentation](https://docs.ansible.com/projects/ansible/latest/collections/ansible/builtin/assert_module.html).

The illustrated kit and map card are fictional. These runs printed text only; they did not build a route or control equipment. Our temporary practice folder was removed after verification.

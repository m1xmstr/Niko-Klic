Our pretend flag needs a color. Four fictional nearest examples vote, but a tie cannot name a unique winner. We explicitly choose an abstention rule: equal blue and gold counts return `ABSTAIN`.

## Count before using a result

The query is 4. The four stored examples are `(1, blue)`, `(3, gold)`, `(5, blue)`, and `(7, gold)`. With `k=4`, all four are included. Their distances from 4 are 3, 1, 1, and 3; nearest order gives gold, blue, blue, gold.

| Case | Blue votes | Gold votes | Actual Python result |
| --- | --- | --- | --- |
| Original examples | 2 | 2 | ABSTAIN |
| Change only the label at 7 to blue | 3 | 1 | BLUE |
| Original examples in a fresh process | 2 | 2 | ABSTAIN |
| Reverse original example order | 2 | 2 | ABSTAIN |

The rule, query, positions, and neighbor count stay fixed. Only one label changes in the second case. A blue result colors our pretend flag on screen; it does not prove a real-world answer is correct.

## Try with a grown-up

Use an existing Python 3 installation. Save the complete example below as `toy_vote.py` in a new practice folder. The video shows the decision rule and recorded votes; this file also calculates nearest examples and counts. It requires only the Python standard library and uses no network, personal data, or devices.

```python
"""Fictional nearest-neighbor votes with an explicit abstention rule."""
from collections import Counter
import json,sys
BASE=[(1,'blue'),(3,'gold'),(5,'blue'),(7,'gold')]
CHANGED=[(x,'blue' if x==7 else label) for x,label in BASE]
def classify(rows,query=4,k=4):
    nearest=sorted(rows,key=lambda row:abs(row[0]-query))[:k]
    votes=[label for _,label in nearest]
    counts=Counter(votes)
    blue,gold=counts['blue'],counts['gold']
    if blue==gold:
        label='ABSTAIN'
    elif blue>gold:
        label='BLUE'
    else:
        label='GOLD'
    return dict(query=query,k=k,nearest=nearest,votes=votes,blue=blue,gold=gold,label=label)
if __name__=='__main__':
    mode=sys.argv[1] if len(sys.argv)>1 else 'base'
    rows={'base':BASE,'changed':CHANGED,'reverse':list(reversed(BASE))}[mode]
    print(json.dumps(classify(rows)))
```

Run each case in a separate process:

```sh
python3 toy_vote.py base
python3 toy_vote.py changed
python3 toy_vote.py base
python3 toy_vote.py reverse
```

Check the returned `blue`, `gold`, and `label` fields against the table. Before the changed run, predict whether it will abstain or choose blue. Before the reversed run, explain why order cannot break a two-to-two tie under this rule.

All four cases were actually executed in independent local Python processes. A separate control with three gold votes also returned `GOLD`. This tiny, two-label, fixed-size demonstration is not a general production classifier. It uses stored examples and an explicit rule; no language model was queried, no neural model was trained, and no accuracy or calibrated probability was measured.

## Why make the tie rule explicit?

Python's [`Counter`](https://docs.python.org/3/library/collections.html#collections.Counter) counts labels. Its `most_common` ordering can place one tied label first because it appeared earlier. Choosing that first entry would hide the tie. Here we compare both counts before choosing a color. Abstention is a design choice in this example, not a promise about every machine-learning library.

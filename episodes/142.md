# Episode 142 — Why Did the Task Skip?

Episode 142 — [Watch](https://www.youtube.com/watch?v=BixxXBItcyA). Public; playback and manual English captions verified November 5, 2026.

Nico wants a message for a pretend camp card. Ansible checks a task's `when` condition: `false` skips this task, while `true` lets it run. A skipped task is not a failed task. These are Boolean values, not quoted strings. See [Ansible conditionals](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_conditionals.html).

## Try the complete example

With a grown-up and Ansible already installed, save this as `camp.yml`:

```yaml
---
- name: Pretend camp message
  hosts: localhost
  connection: local
  gather_facts: false
  tasks:
    - name: Tent message
      ansible.builtin.debug:
        msg: TENT READY
      when: false
```

Run only the local practice task:

```sh
ansible-playbook -i localhost, --limit localhost camp.yml
```

Our recorded output includes:

```text
TASK [Tent message]
skipping: [localhost]
```

The recap has `skipped=1`, `failed=0`, and `changed=0`. The task's message is absent.

Now change only `when: false` to `when: true`. Predict what happens, then run the same command. Our recorded task output includes:

```text
ok: [localhost] => {
    "msg": "TENT READY"
}
```

This time the recap has `ok=1`, `skipped=0`, `failed=0`, and `changed=0`. A fresh independent run of the false version skipped again. All three runs used the same single debug task on localhost; no remote systems were contacted.

The [debug module](https://docs.ansible.com/projects/ansible/latest/collections/ansible/builtin/debug_module.html) prints a message. It does not build a tent or control equipment. The animated card illustrates the recorded result.

## Practice together

Make two paper cards marked `false` and `true`. Choose one and predict whether the task prints its message. Then compare the real output with your prediction. Changing the condition decides whether this task runs; it does not change the message itself.
